# 已有服务器实测

以下来自整理项目之前的输出，代码整理后未重新全量跑数据。CPU 双 Xeon 8352V、72物理核/144逻辑核，GPU A100 80GB。视频主要为24个 CPU 工作进程，单解码器2线程。倍速是轨迹时长除墙钟时间，多路相机总时长倍速另算；不是通用性能承诺。

| 场景 | 样本/结果 | 轨迹时长倍速 |
|---|---|---:|
| HiFi-UMI CPU，块检测开，头部LK | 全1125回合，1054 PASS /69 REVIEW /2 FAIL，约37分32秒 | 8.49× |
| HiFi-UMI CPU，无块检测 | 302回合，实际5分22秒，286 PASS /16 REVIEW | 15.21× |
| 直接每回合 NVDEC | 112回合，实际5分43秒 | 5.17× |
| 四GPU持久NVDEC + CPU算子 | 198回合，实际5分26秒 | 10.19× |
| GPU像素算子四卡 | 超预算中止、分类差异未解决 | 不作为有效性能结论 |
| 新 Action-State（初次跑） | 80回合、99,140帧；55.03分钟，计算102.28秒、含8张图136.82秒 | 计算32.28×；含图24.13× |

HiFi-UMI为6路相机，15.21×轨迹约对应91.24×相机时长。CPU无块阶段CPU累计耗时比例：解码41.0%、头部LK25.0%、灰度10.4%、signalstats7.2%、时序6.8%、导出1.4%、其他8.1%。这是各工作进程累计计时的分解，不等于墙钟上可直接相加的并行耗时。

动作初次跑50 PASS /3 REVIEW /27 UNASSESSABLE，候选延迟中位数约0.133秒；27条全部是峰值优势不足0.02，不是低相关或窗口不足。1298、1320因反向比例约10.2%、10.4%待查；1330无响应比例约54.4%。阈值未校准，不能据此直接删除。

初次动作运行之后将逐关节 SciPy 调用向量化，并将红色窗口绘图改为集合绘制。已用合成3帧延迟与单条实际回合确认一致；表内保留初次全量计时，没有拿优化后的局部计时替代全量实测。
