# EgoDex CPU/GPU流水批推理

```bash
cd /data_all/cenyj
PYTHONDONTWRITEBYTECODE=1 .venvs/agibot_gripper_qc/bin/python scripts/egodex_yolo_pipeline.py \
  --output lerobotv3_output/egodex_yolo_dual_gpu_pipeline \
  --gpus 0,1 --cpu-workers 4 --batch-size 8 --flush-ms 30
```

输出目录必须不存在。GPU需在可访问设备的环境运行；脚本拒绝静默CPU回退。复用已有环境、权重，不安装TensorRT，也不修改系统或原数据。

## 已实现

- 仍为4个CPU解码进程、每视频最多2线程，保持原全程解码/HDF5可读性/帧数与PTS检查，质量和手部2Hz抽样。
- 两个独立GPU进程，每卡常驻一份YOLOv8n人手模型，CUDA FP16、640输入、0.25阈值。仅PyTorch FP16，未使用TensorRT或INT8。
- CPU采样后继续解码，不等待每张图的检测；跨视频共享有界输入队列，两个GPU竞争取任务、组批处理，最多8张，收集等待上限30ms。
- CPU端提前执行与YOLO letterbox一致的等比例缩小，减小进程间传输量；检测框缩放回原视频坐标。画质指标及冻结hash仍基于原解码图像。
- 每CPU进程独立结果接收线程，异步收取/按token归位；回合解码完成后再等待尚未完成的结果，检查GPU处理总数与CPU样本总数一致。
- 输入队列容量64帧，单CPU未完成请求最多64；结果队列独立，不让长视频积压造成结果回压死锁。
- 不再渲染旧Palm候选对照。实际FAIL/REVIEW仍调用原导出器，生成原速问题片段、2Hz抽样速览和截图，每回合最多两个原速片段。没有告警就只保存CSV/JSON/网页，当前不生成正常样本视频。
- 首尾裁剪、运动质检、LeRobot转换和源文件删除仍未启用。

## 同批一次实测

20条视频425.73秒，12772帧完整解码，876个2Hz+尾帧点。

- 完整执行35.93秒，11.85倍。
- GPU进程启动/导入/加载/热身7.27秒；排除此整个启动阶段为14.85倍，该口径不是只排除加载。
- CPU解码/GPU推理重叠阶段27.06秒；关闭GPU/复核输出/CPU退出1.50秒（本轮0告警，无实际媒体输出）；报告0.09秒。
- 两卡各438张，批次多为1～2张；最大8只是上限，不代表实际始终满批。
- 与前一轮单卡四模型46.55秒/9.15倍相比，还去掉了旧对照视频。前一轮核心阶段25.50秒，本轮27.06秒，包含阶段位置不同的CPU子进程启动开销；不能宣称双卡本身带来核心处理提速。
- 20PASS，0REVIEW/FAIL，与上轮判定相同。采样时刻、完整解码帧数、画质指标与上轮完全一致。具体模型计数差异见verification.json；没有人工真值，不能宣称检测准确率。

结果入口`lerobotv3_output/egodex_yolo_dual_gpu_pipeline/index.html`。本轮无新问题，网页不再显示旧模型的三条未检出视频。告警复核视频功能保留，不能因为本批无告警就误认为功能被关闭。

## TensorRT FP16与算子融合

当前FP16只代表半精度计算，仍使用PyTorch后端。TensorRT是NVIDIA推理运行时，会针对GPU选择算子实现、内存布局并进行可行的计算图融合。例如卷积/偏置/激活符合融合条件时可减少中间张量读写与kernel调用；并非所有算子都能融合，部分卷积/BN融合在当前推理路径里已经存在。以后使用TensorRT FP16是另一项独立优化，需要匹配当前CUDA/驱动并构建引擎，本轮未实施。
